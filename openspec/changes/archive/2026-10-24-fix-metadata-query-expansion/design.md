## Context

基线为已归档并推送的 `76a878e`。动机见 proposal.md；本变更不重开此前已确认的 YAML 结构、来源顺序、Worker 隔离、私有路径导出或 Pi 原生启动生命周期。

已检查的实施接缝：
- `model-metadata.ts:160` 的 `idCandidates()` 分别生成字符串变体；`firstHit()` 在首个命中处返回。`indexCreators()` 只保存 canonical 厂家集合，`compileEntry()` 又用原始型号查原厂表。
- `metadata-compile-worker.mjs` 仅传递 `snapshot.providers`；SDK 的 `/snapshot` 还导出 `models`。SDK 类型明确它是按 canonical ID 索引、与 provider 无关的模型资料。
- `index.ts` 的自动富化当前允许外部 name 替换网关名称；notes/error 经 `pi.appendEntry()` 持久化。Pi 原生 `ctx.ui.notify()` 只更新 UI；CLI 无 UI 时可写 stderr。
- 已有纯编译器、真实 Worker、注册命令、provider 生命周期和 loader 测试；测试用 call-time `CompileDeps` 注入，不再引入环境变量旁路。

研究证据是候选覆盖量，不是上线保证：安装数据包 `@opencode-ai/models 0.0.113`、`modelparams 0.0.72` 下，349 个模型的基线实现有 214 个来源条目命中，其中 204 个含有效能力资料，另 10 个不能只凭名称计作能力命中；大小写／分隔符 regex 可在来源中找到 279 个模型的字符串候选，结合完整 canonical 和统一资料的内存对照为 273 个。另有 70 个没有字符串候选，多个 canonical 型号也不能靠 regex 任意裁定。数字不作为依赖最新 npm 数据的 CI 硬编码阈值。

实施后的同数据回放确认有效能力资料为 204 → 273（新增 69、丢失 0），分为完整命中 224、部分来源缺失 49、完全未命中 76；记录位于 `/var/tmp/oapi-query-coverage-JmfFmh/results.json`。

## Goals / Non-Goals

**Goals:**
- 自动查询只改变内部候选，不改变公开身份；对同一末段跨渠道得到一致候选。
- 在身份可证实的前提下利用全部命中，修复已有资料被丢弃的情况，并能解释实际字段来源。
- 自动诊断不进入会话 JSONL、对话上下文或新的日志存储。

**Non-Goals:**
- 不新增配置开关、来源通配符、用户正则、canonical 映射表或依赖。
- 不重排 `claude-5-fable` 等词序，不自动去 `model_` 前缀，不借显示名识别私有 ID，不剥离 `-1m`、`-500k`、`:free`、`-compact` 等语义修饰；这些均未纳入本次范围。
- 不修改宿主、缓存刷新时机、推理协议、认证、模型成员、历史 JSONL；不恢复查看弹窗。

## Decisions

### D1 把查询、身份与字段来源分开

保留 `publicId` 作为配置匹配、显示和请求路由身份。内部流程为：末段输入 → 全部字面命中 → canonical 身份判定 → 来源筛选与字段选择 → 固定编译结果。模型显示名在自动富化后仍从上游身份读取，再按已有顺序应用用户 overrides 与 Pi modelOverrides。

备选是把输入直接改写成一个标准 ID；否决：会混淆路由身份与查询身份，不能保存多个命中，也不符合用户要求。

### D2 编译期 regex 全量查询

1. 从公开 ID 最后一个 `/` 后提取输入；字面精确命中为第 0 层。
2. 对输入按连续的空白、`_`、`.`、`-` 分隔符切段，转义其余字符，以分隔符等价字符类连接，并加入整串边界和大小写不敏感标志。例如 `Claude Fable 5.1` 得到内部 regex literal `/^Claude[\s._-]+Fable[\s._-]+5[\s._-]+1$/i`。来源有命名空间时匹配其末段，但命中对象保留完整 key/id。
3. 复用现有去末尾 `-YYYYMMDD`／`-YYYY-MM-DD` 的日期回退，作为更低一层独立查询；不生成任意日期或版本通配符。
4. 遍历来源 key/id 别名及统一 canonical 型号索引，收集每一条命中，不在首个命中返回；重复原始记录按来源身份去重，并保留命中层级。

查询 regex 只在 Worker 内存在。相同末段在一次编译中复用查询结果，避免多个渠道重复扫描；不引入跨刷新缓存。pattern 的可变部分只有经过转义的字面块和固定分隔符类，不接受用户正则、不使用 `.*` 或嵌套任意量词。最终结果不保存可执行 regex。

稳定排序只用于展示候选和等价无冲突别名，不用于裁决不同型号：来源顺序、厂商组顺序、匹配层级均优先于展示排序。所有层级命中都可导出，只有最高可用层级参与当前身份判定。

### D3 保存完整 canonical 并在恰当层级消歧

新增内部 canonical 身份信息，至少含原始 canonical ID、厂家组与 canonical 型号；不能只存 creator。
- 最高匹配层级中，统一 `models` 表直接匹配到的 canonical 是更强的身份依据；没有时使用 provider 记录的 `canonical_model_id` 线索。
- 保留现有厂商别名组。别名归并不等于把同厂家所有型号归并。
- 不同厂家冲突仍按配置错误处理；同厂家不同型号无法唯一裁定时仅将该条目记为身份歧义，保留候选，继续后续来源。
- 已确认的 canonical 型号用于实际来源定位；modelparams 在自身 namespace 内尝试对应字面原始型号和 canonical 型号，仍按原厂别名组及 authType 约束筛选。
- 用户写死 provider／第 4 段时，保持其已有精确查询约束，不被自动全站发现取代。

例：来源 `deepseek-v4-flash-fast` 的声明是 `deepseek/deepseek-v4-flash`，应查后者，而不是再去 deepseek 表中找旧别名。对于 `gemini-3-1-pro` 同时指向 preview/customtools，不能按第一条或字母顺序猜。

### D4 原厂 API 记录优先，统一 canonical 资料只作兜底

扩展 `SourceTables.modelsDev` 以接收 `providers` 和 `models`，扩展索引以直接读取完整 canonical ID。两种 shape 独立校验；其中一种不可用不使另一种整体失效。

仅自动 `@creator/api_key` 路径使用此兜底：同一 canonical 的具体原厂记录字段优先，缺失／无效字段才从统一资料补入；两者都缺时继续用户链的下一来源。不存在具体 provider 条目时，统一资料本身也可形成一个固定逻辑来源条目。不把统一资料等同于原厂当前仍提供该 API 产品，导出必须标明实际来源。

显式来源、字面型号与 subscription 条目不自动引入通用 API 限额。聚合商记录只提供身份线索，不提供限额。备选是任选仍收录型号的转售商；否决：其限额可能并非原厂或用户套餐限额。

### D5 候选与字段溯源是编译结果，不进入 Pi 模型身份

在 `CompiledModel` 附加全部字面候选和 canonical 选择／跳过原因；在编译条目上记录实际采用字段的溯源，区分 provider 记录和 canonical 资料。一个模型的原厂字段与 canonical 兜底字段可同时存在，故溯源按字段记录，而不能只给整个模型贴一个来源标签。

固定链的四段字符串格式不变。统一资料没有具体 API 条目时，使用 canonical 厂家／型号形成逻辑身份，并用字段溯源明确它来自统一资料。用于执行的字段在编译时已确定，运行时不再枚举来源或执行 regex。Pi 只收到原始公开模型和富化能力字段，不收到新的公开模型或待匹配候选。

同来源同层级别名若指向同 canonical 但能力字段冲突，保留完整候选，跳过冲突记录组，继续后续来源；不按返回顺序选择。精确记录优先于低层级 regex 别名，低层级冲突不能推翻已确定的更高层级身份。

### D6 分类汇总代替误导的 unresolved 总数

对启用外部链的模型统计三类：完整命中、部分来源缺失、完全未命中；明确禁用外部链另计。判断基于有效外部能力字段而非仅条目存在或 name 存在。分类互斥，数量守恒。通知只显示一条短汇总；导出文件保留逐模型候选、来源缺失／身份歧义／字段冲突等原因。

### D7 用原生临时通知替换会话条目

删除 `ERROR_ENTRY`／`NOTE_ENTRY` 的报告写入和专用渲染器，不用 `sendMessage`、`sendUserMessage` 或其他会话事件代替。复用 `session_start` 取得的最新 ExtensionContext：有可用 UI 时 `ctx.ui.notify(message, severity)`，无 UI 或上下文时仅 stderr；CLI stdout 保持正常协议。RPC 有可用 UI 时遵循宿主的原生通知协议，不自己拼 RPC 消息。

不新增通知管理器、存储或异步队列。保留连续报告的内存去重，空报告能清除旧去重状态；会话切换更新上下文，关闭时清除引用。只对本次仍有效且成功发布的刷新报告成功／降级结果；取消或被新刷新取代的结果不发过期通知。配置错误仍以 error 明确提示，但不写 JSONL。

所有通知先复用现有凭证脱敏及控制字符转义；通知异常不能掩盖原始目录错误或导致推理重试。原生通知可能保留在当前终端可见内容里，“临时”指插件不写会话持久化，而不是承诺定时消失。

### D8 真实入口验收而非替代入口

- 纯函数夹具验证 regex 收集、完整 canonical、兜底与排序，不依赖在线数据的固定总数。
- 通过真实 Worker 验证两个数据 shape 传递、结构降级、错误和取消；保持无裸包名导入检查与 terminate 回收。
- 通过实际 provider/命令 handler 验证公开 ID／显示名不变、overrides 优先级、分类输出及临时路径。
- 用安装的 Bun Pi、隔离 agent 目录、loopback 网关和 tmux，触发成功、部分缺失与配置错误；比较该隔离会话 JSONL 前后，确认无新增插件 note/error 条目。测试服务器与客户端放在同一个有超时、可统一关闭的 harness 中，避免跨工具脱离服务器。
- 普通暖缓存 CLI 仍零请求，显式 `--refresh --list-models` 才联网；不重开启动优化。
- 最终树验收（2026-10-24）：父会话全量测试 564/564，全部已知审查复现通过；真实 Bun/tmux 记录 `/var/tmp/oapi-query-accept-BMhzlG/results.json` 确认原始公开 ID／显示名／请求型号不变、成功及错误通知可见、真实会话 8 条记录但插件诊断 0 条、私有导出退出后保留、暖 CLI 255ms/0 GET。最终两项物理别名归并与导出证据隔离由 reviewer-final 独立复核关闭。

## Risks / Trade-offs

- [分隔符等价可能发现更多候选而非唯一结果] → 全部保留、按层级和 canonical 判定；多型号或同级冲突不猜。
- [放宽名称会误伤容量、套餐或版本变体] → 只处理既定分隔符与大小写，不新增词序、显示名、容量／套餐后缀规则，显式型号仍字面查询。
- [统一模型资料与具体 API 限额不同] → 原厂具体记录字段优先，通用资料仅为自动 API 链补缺，并导出字段来源。
- [浮动数据包使真实命中数字变化] → 数量作为研究基线和实施前后对照；CI 断言固定夹具与身份不变，不把 273 设为硬性上线门槛。
- [候选全量收集增加编译结果大小] → 同来源记录去重、同末段复用查询；不截断用户要求的候选，不把完整 SDK 快照传回主线程。
- [旧提示仍保存在旧 JSONL] → 本变更只停止新增，不自动改写历史；普通模型缓存与主动临时导出继续保留。

## Migration Plan

1. 保持 YAML 与链语法不变，在 README 说明查询展开仅作用内部、显示名保护、统一资料来源、分类统计和临时通知行为。
2. 实施后使用显式目录刷新重新富化已有缓存；不在插件工厂里自动联网重建。
3. 回滚时回到上一插件版本并刷新目录；不为回滚清理或重写用户会话 JSONL。此规划不执行提交、发布或回滚。
