## Context

动机及范围见 `proposal.md`。

现有实现的关键边界：

- `metadata-config.ts` 负责 YAML、旧字段与已知字段校验；根级和规则级均接受 `fill_missing_only`，空链目前合法。
- `model-metadata.ts` 的 `compileCatalog` 仅接收公开 ID 与外部数据表；Worker 不持有原始上游响应。`externalFields` 已按来源顺序逐字段选择首个有效值，随后 `makeResolver` 通过 `mergeMetadata` 的布尔开关合并上游。
- `metadata-compile.ts` 的 `effectiveChainFor` 另写了一份默认链；`neededSites` 决定数据包加载，零站点已有不启动外部数据 Worker 的路径。
- `index.ts` 的映射阶段分别持有原始上游行和已合并能力字段，最后补默认值、应用插件 RFC 7396 patches；Pi 覆盖仍在其后。当前 `mapModel` 对 `capabilities.effort_tiers` 的直接回退，以及降级提示固定的 “using upstream values”，都会绕过新的无 `@self` 语义。
- `/provider-metadata` 的入口位于 `index.ts`，已持有同次读取的上游模型清单；`metadata-view.ts` 目前只接受编译结果并输出旧布尔模式。
- README 当前约 477 行，混合安装、环境变量、传输恢复、元数据配置与开发细节。`docs/` 已有压缩和检查点两篇专题；`package.json` 已打包整个 `docs/`，无需为此次拆分改变发布文件列表。
- `allow-optional-model-id-separators` 已完成但尚未归档，修改了查询归一化同一 Requirement。本次 delta 在调整未命中回退条件时保留该变更的全部可选分隔符语义，不重做匹配器，也不自动归档其他变更。

## Goals / Non-Goals

**Goals:**

- 让来源顺序成为能力字段选择的唯一依据，复用现有规范化、校验与逐字段优先级。
- 在现有 Worker/主线程边界内表达具体上游来源，不传递凭证或常驻完整外部数据。
- 默认用户继续外部优先、上游兜底；显式外部链可以严格替换，错误配置清晰可迁移。
- 建立短 README 与按任务组织的详细文档，准确说明真实默认值而不改变它们。

**Non-Goals:**

- 不增加新来源、配置开关、通用管线框架、迁移器或依赖。
- 不调整模型 ID 匹配、canonical 消歧、认证、成员筛选、传输重试、压缩、检查点或数据包更新策略。
- 不修改既有默认限额、推理档位映射或成本占位，不将文档拆分变成新的站点/索引系统。

## Decisions

### 1. 使用有类型的有序来源，而不是隐式模式

配置层接受完整 `@self` 条目。先按现有规则层叠确定 chain，再原地展开 `@default`；随后将外部条目编译为原有固定记录，将每个 `@self` 编译为带具体 `publicId` 的上游来源节点。编译来源使用明确的上游/外部判别类型，放在同一有序列表中；不为上游伪造 site/provider，也不留下需要再次解析的关键词字符串。

执行时在上游节点位置读取当前模型已有的原始行，通过 `normalizeFields` 取得能力白名单；和外部节点统一遵循每字段首个有效值。重复的上游来源按普通顺序处理，第一次有效值已占用的字段不会被后续节点改变，不新增去重开关或特殊优先级。

替代方案：用 `chain.includes("@self")` 派生布尔开关。拒绝，因为会丢掉用户已确认的位置语义；单独记录一个上游插入下标也会产生并行状态，不如来源列表直接表达。

### 2. 严格区分身份、能力、默认值与最终 overrides

身份及路由仍由原始上游行决定，只有能力字段受来源链控制。`mapModel` 收到已解析能力对象时不得再从原始行取未声明来源的能力；直接映射未富化原始行的既有调用仍保留原有行为。尤其要关闭严格替换下对 `capabilities.effort_tiers` 的旁路回退。

顺序保持：来源能力规范化与选择 → `mapModel` 补最终默认值 → 按规则顺序应用插件 patches → Pi `modelOverrides`。`[]` 作为明确 effort 值仍有效，不能按缺失处理。不得为了“完整替换”而抹掉公开 ID、网关显示名、provider、api、baseUrl 或成员过滤需要的原始信息。

替代方案：将上游整行清空后执行映射。拒绝，因为会破坏身份和过滤；始终用上游作为初始能力对象也不可取，因为无 `@self` 时仍会暗中保留能力。

### 3. 收紧配置边界并复用同一默认链

用户已确认：

- 内置默认链为 models.dev 原厂 API → modelparams.dev 原厂 API → `@self`。
- 根级及模型规则的显式 `chain: []` 均报错；省略根级链采用默认，省略规则链表示继承。仅上游必须写 `["@self"]`。
- 根级与规则级 `fill_missing_only` 纳入旧字段错误；无论值是什么、是否同时有 `@self`，都不兼容执行。

错误保留完整路径和具体迁移提示，沿用已有配置失败不发布、保留已验证目录的处理。删除配置及编译类型中的布尔模式，不用新名字保留同一个开关。`metadata-compile.ts` 引用统一的默认链，避免新增 `@self` 后两处默认值漂移。

替代方案：兼容一个版本或在加载时自动改写用户 YAML。用户已选择直接报错迁移，因此不实现转换器，也不写用户配置文件。

### 4. 沿用站点按需加载与固定编译计划

上游节点不需要外部站点，也不参与 `@creator` 或候选解析；仅上游链复用现有零站点路径。混合链仍按实际外部条目计算所需站点；对 `@creator` 保留 models.dev 身份数据的既有依赖，不因为出现 `@self` 就删掉它。

外部缺失或降级只跳过对应节点；后续只有声明了上游节点才读上游，否则补最终默认值。降级通知改为准确的来源跳过描述，不再一概声称回退上游。`externalChain` 的含义保持“是否声明外部来源”，不再用来源列表长度判断；上游字段不能充当外部匹配成功的证据。

替代方案：为 `@self` 新建适配器、数据包或 Worker 协议。无必要；上游行已在主线程可用，外部 Worker 的数据生命周期不变。

### 5. 导出接受最小上游上下文，不复制整个响应

`/provider-metadata` 使用同次获取的上游行，将按公开 ID 关联且经过能力白名单规范化的只读上下文传给渲染器，用于展示固定上游节点可提供的字段及其实际位置。Worker 仍只处理 ID 和外部数据，不接收原始响应或凭证。发布与导出复用相同规范化与来源顺序，不再分别解释布尔模式。

配置区可以展示用户写的 `@self` / `@default`；固定执行区展示具体上游类型与公开 ID，而不是待解释关键词。现有外部候选、canonical 字段标记、脱敏、终端转义、临时文件权限和不发布目录约束均保持。展示“来源可提供的字段”不得混同为“这些字段全部成为最终值”。

替代方案：把整份原始 catalog 放进编译结果。拒绝，因为增加敏感字段泄露面和跨线程数据量；只输出布尔模式又无法核对顺序。

### 6. 记录真实默认值，不调整默认策略

源码依据：`index.ts` 的 `DEFAULT_CONTEXT_WINDOW`、`mapModel`、`parseEfforts` 与 `thinkingLevelMap`。在 `docs/model-metadata.md` 维护下表，说明默认在来源选择后、人工覆盖前计算：

| 字段 | 当前回退/固定行为 |
| --- | --- |
| `contextWindow` | 来源未给有效上下文时为 128000 tokens，不是 131072 |
| `maxTokens` | 来源未给有效输出上限时取解析出的 contextWindow；上下文也缺失时才是 128000 |
| `reasoning` / `thinkingLevelMap` | 未声明有效推理档位时为 false / 不生成档位映射 |
| `input` | 未声明图片输入时为 `["text"]` |
| `cost` | 无用户覆盖时四项固定为 0；目前没有外部价格富化，不代表模型免费 |

补充 200000 上下文但无输出上限 → 输出回退 200000 的示例。说明这些是保持模型可注册的占位回退，并非真实能力保证；手工覆盖 contextWindow 不会自动重新计算此前生成的 maxTokens。清理现有文档中“context/output 都固定 128K”及“explicit gateway limits always win”的误导表述，后者与外部优先规则不符。

替代方案：趁机改成更小的输出默认值或新的价格来源。超出请求范围，本次只准确说明已有行为。

### 7. README 只做入口，详细内容各有唯一归属

保留现有英文使用文档语言，不额外翻译。README 只保留简介/特色、安装命令、必要的一行宿主兼容前提、`/login openai-api-extension` 与最短使用步骤，以及详细文档链接和许可证信息；不展开环境变量或原理。不设硬性行数门槛，以能快速完成首次安装登录为验收。

| 目标文档 | 迁入/维护内容 |
| --- | --- |
| `docs/configuration.md` | 凭证保存与环境变量优先级、base URL、首次刷新与离线行为、通用 Pi 配置和 per-model overrides 入口 |
| `docs/model-metadata.md` | 来源链、规则与人工覆盖、canonical/查询约束、默认值表、配置迁移、编译导出、数据包检查与更新 |
| `docs/transports.md` | transport 设置、连接状态、WS/SSE 重试与恢复边界、请求头及有效认证的传输约束 |
| `docs/request-compression.md` | 保持既有压缩专题与宿主能力要求，不复制其原理段落到其他文件 |
| `docs/response-checkpoints.md` | 保持既有检查点专题、恢复/引用修复限制及安全边界 |

不另建 docs 索引文件或文档框架。将旧 README 章节映射到上述目标，修复迁移后的相对文件路径和锚点；现有两篇专题末尾的 “setup and transports” 链接改指具体新位置。保留安装兼容条件、凭证优先级、首次发现命令、恢复安全限制等必要信息，不能用“精简”作为删除依据。

## Risks / Trade-offs

- [显式外部链升级后不再保留上游] → 在迁移说明突出必须显式放入 `@self`；内置默认链末尾加入上游节点，未配置用户不变。
- [旧空链与旧开关阻止新目录刷新] → 错误提示提供对应非空写法，保留旧目录、凭证及离线恢复；不静默改变用户文件。
- [字段别名、嵌套推理值旁路或提前补默认值改变优先级] → 在现有解析器和最终目录映射边界覆盖位置交换、缺失、无效值、空 effort 与严格替换案例。
- [上游来源使诊断和匹配统计误报] → 不把上游当外部候选，按外部实际命中分类；导出仅展示必要的规范化字段。
- [同一 Requirement 存在未归档的已完成 delta] → 保留可选分隔符全部既有场景；将来归档时核对重叠块，不能让旧 delta 恢复无条件上游回退。本次不归档其他变更。
- [拆分后细节丢失或本地链接失效] → 按旧标题逐项核对迁移去向，验证 README 和所有 docs 的本地文件/锚点链接，并通过打包 dry-run 确认新专题随包发布。
- [默认限额或零成本被当成真实承诺] → 用精确数字、派生示例和占位说明区分，不用“所有模型保证 128K/免费”类表述。

## Migration Plan

实施时将代码、配置错误提示与对应文档一起交付；不做用户文件自动迁移、不重写已有目录缓存或会话。

| 原有意图/写法 | 新写法 |
| --- | --- |
| 未配置链与开关 | 继续省略，采用默认外部链加末尾 `@self` |
| 旧 `fill_missing_only: false` | 删除开关，将 `@self` 放在生效外部链之后 |
| 旧 `fill_missing_only: true` | 删除开关，将 `@self` 放在生效外部链之前 |
| 旧 `chain: []` 禁用外部来源 | `chain: ["@self"]` |
| 显式外部链，希望仍保留上游未被覆盖字段 | 在所需优先级位置添加 `@self` |
| 显式外部链，希望完全替换能力元数据 | 不添加 `@self` |

多规则旧开关继承要按最终命中链人工迁移，不能仅机械删除布尔字段。回滚到旧代码前需恢复匹配旧语法的配置，因为旧解析器不识别 `@self`；用原配置备份恢复，不借回滚之名修改凭证、缓存或会话。README/docs 拆分只改变文档位置，现有专题保留原路径。
