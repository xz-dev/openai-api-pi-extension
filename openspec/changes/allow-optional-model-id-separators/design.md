## Context

动机与范围见 `proposal.md`。当前 `model-metadata.ts` 的 `buildQueryRegex` 按 `/[\s._-]+/` 拆分，再用 `[\s._-]+` 连接，丢失原始分隔符数量。`collectHits` 对原查询及去日期后缀查询调用它，`collectTableHits` 和编译入口复用同一命中收集机制。

现有 `new RegExp(..., "i")` 已实现大小写不敏感，命中保存来源原始 `sourceId`、`sourceKey`，无需改写 ID。`tests/model-metadata.test.ts` 中 `separator runs are interchangeable, never removable` 与 `single boundary separators match, never delete` 明确禁止删除，必须修正这些旧断言；无分隔符查询不能凭空插入分隔符的反向断言继续有效。

本设计用于提前固定兼容性边界：允许删除，但禁止新增位置和一换多。既有主规范“查询 ID 归一化”由本变更 delta 整块更新；另一个未归档变更修改该能力的不同 requirement，不改其规划文档。

## Goals / Non-Goals

**Goals:**
- 在一个共享 regex 构建点保存每个分隔符的位置与数量，避免不同元数据来源行为分叉。
- 搜索宽容性不泄漏到身份、输出拼写或显式字面查询。

**Non-Goals:**
- 不新增配置、别名生成器、全局小写化索引或对来源 ID 的预处理。
- 不实现来源侧的双向删除、不在裸查询中插入分隔符、不改 glob 匹配。
- 不改变 canonical 解析、字段选择、链排序或原有日期后缀识别规则。

## Decisions

### 逐字符构造可选分隔符

保留整串锚点及 `i` 标志。遍历原查询字符，每个属于既有 `\s`、`.`、`_`、`-` 集合的字符输出一个 `[\s._-]?`，其余字符沿用现有 regex 元字符转义，再拼接。沿用空串和纯分隔符不生成 regex 的保护。

示例：`A--B` 生成 `^A[\s._-]?[\s._-]?B$`，`A-B` 只有一个可选字符类。首尾分隔符同样处理；空白继续使用现有 `\s` 范围，不悄悄收窄为 ASCII 空格。

不采用 `+` 或 `*`：两者均允许单个分隔符扩张为多个。不继续按分隔符 run 折叠：会丢失两个查询分隔符允许匹配两个来源分隔符的数量信息。不删除来源分隔符后再比较：会使裸查询匹配带分隔符记录，破坏方向与位置约束。

### 保持搜索与结果身份分离

不对公开 ID、来源表 key、`sourceId` 或最终条目执行 `toLowerCase()`，不将 regex 拼出来的变体作为查询结果。继续返回命中的实际记录。`collectHits` 的精确匹配保持 level 0，大小写、分隔符替换及删除命中均为 level 1，去日期后缀命中保持 level 2。

显式第 4 段继续使用已有字面查找路径，不因本次变更获得大小写或分隔符宽容。新增候选沿用现有确定性排序、去重与 canonical 歧义处理。

### 通过编译入口验证，不导出内部 helper

复用现有 fixture 和 `compileCatalog`/`probeModel` 验证候选、字段、等级及输出拼写。增加四类分隔符的替换/删除矩阵，内部和首尾数量边界，大小写与来源完整 ID 保留，以及去日期后缀/显式链约束。不为测试新增公开函数或运行时参数。

## Risks / Trade-offs

- [兼容性收紧：原先一换多的候选不再命中] → 验收明确检查 `a-b` 不匹配 `a--b`，按新规则处理未匹配，不回退到宽松 `+`。
- [删除分隔符新增同级 canonical 冲突] → 保留现有歧义诊断与拒绝混合规则，测试来源枚举反转仍确定，不以首条候选消除冲突。
- [长分隔符 run 产生连续可选量词，可能增加 regex 回溯] → 保持现有空/纯分隔符保护及锚点；本次不加入新的长度限制或性能架构，若后续出现实测瓶颈再优化等价构造。
- [搜索宽容被误用于输出或字面链] → 用混合大小写、命名空间来源和显式第 4 段反例固定边界。

## Migration Plan

无需数据或配置迁移。实施后执行元数据测试与 `npm run check`，下一次元数据编译使用新规则；不重命名已公开 ID，也不自动重写用户配置。若需回滚，恢复共享 regex 构建与对应旧行为测试即可，既有来源数据不变。
