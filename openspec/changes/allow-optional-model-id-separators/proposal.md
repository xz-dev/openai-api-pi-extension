## Why

当前模型 ID 内部查询将连续分隔符折叠成一个可匹配任意正长度的片段，既无法命中删除分隔符的来源记录，也允许一个分隔符匹配多个分隔符。需要改为逐字符一换一或一换零，同时明确搜索不区分大小写、结果仍保留原始 ID 拼写。

## What Changes

- 查询中每个空白、下划线、点号、横线独立匹配零个或一个四类分隔符，包含内部及首尾位置；一个分隔符不能匹配两个，连续 n 个分隔符最多匹配 n 个。
- **BREAKING**：原先一个查询分隔符可匹配多个来源分隔符的行为不再支持；无分隔符的查询不新增分隔符位置。
- 保留已有的大小写不敏感搜索；公开 ID、来源 ID、来源 key 与最终条目保持原始大小写，不以小写或归一化字符串替代结果。
- 保持字面精确命中优先于内部 regex、内部 regex 优先于去日期后缀回退，以及原有歧义处理。
- 保持显式链第 4 段的字面精确查询约束；不开放用户 regex，不改用户规则 glob。
- 替换现有“分隔符不能删除”的回归断言，增加禁止一换多、连续分隔符数量上限、大小写和原始结果拼写验收。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `model-metadata-resolution`：调整“查询 ID 归一化”，将分隔符匹配限定为逐字符替换或删除，明确大小写只影响搜索、不改写输出。

## Impact

- `model-metadata.ts`：共享 `buildQueryRegex` 及其 `collectHits`、`collectTableHits` 使用路径；无新增依赖、配置或公开接口。
- `tests/model-metadata.test.ts`：现有分隔符、候选收集、匹配等级、显式链与大小写回归。
- 候选集合既可能新增省略分隔符的记录，也可能排除分隔符数量过多的记录；新增匹配可能暴露 canonical 身份歧义，继续使用既有拒绝混合与诊断规则，不选择首个候选规避冲突。
- 与未归档的 `manage-metadata-updates-and-prefix-output` 修改同一能力的不同 requirement，无需改写该变更。
